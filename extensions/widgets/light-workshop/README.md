# 光线机关工坊 · Light Workshop

6×6 光学解谜小组件。转动镜子，让光线点亮接收器；也可以编辑关卡，通过现有对话或浮动对话小窗让 AI 协助解题、出题。

## 使用

- 六道内置关卡：第一束光、绕个小弯、拾级而上、曲径通明、峰回路转、光之缎带；最少转动次数分别为 2、2、4、4、5、6。
- 解题时只允许旋转固定位置的镜子，支持撤销、重置和下一关。
- 出题时可摆放光源、接收器、镜子与墙壁。再次点击镜子可旋转；光源方向由方向按钮指定。用对应工具移动光源或接收器，橡皮不会删除必需元件。
- 每关最多 8 面镜子；检查全部 256 种以内的朝向组合，拒绝无解或初始已完成的题目。最少步数统计从初始朝向到任一解的最少旋转次数，不是光线经过的镜子数量。
- 自定义关卡保存在组件级 storage，最多 30 个；棋盘、操作记录与位置高亮保存在页面 state。保存使用版本检查，读取失败不会覆盖已有作品。

## 通过现有对话操作

小组件只提供棋盘和编辑工具，没有 AI 面板、会话选择器、聊天框或任务按钮。所有能够访问当前实例的会话都可直接读取和操作，无需加入、席位、单独授权或任务分配。提示与解释回复现有会话；需要指出位置时，只在棋盘上高亮镜子。

| 接口 | 作用 |
| --- | --- |
| `readBoard` | 返回当前布局、光路、进度和即时结果；完成后仍可读取，不返回求解答案 |
| `rotateMirror` | 旋转一面镜子，返回新光路和通关结果 |
| `highlightMirror` | 标记镜子而不旋转；传入 `null` 清除标记，不保存或显示聊天文字 |
| `validatePuzzle` | 返回拟议布局的可解性、解的数量和最少步数，隐藏具体解法 |
| `submitPuzzle` | 用户要求新关卡时使用；验证成功后替换当前关卡，交给玩家 |

模型按用户要求在当前对话回合中调用接口：轻提示只回复文字，示范一步只旋转一次，连续解题逐步检查光路直到结束。组件不发送行动通知，不维护参与者、任务授权或自动续跑回合；停止生成由现有对话控制。

页面操作与接口共用业务规则，保留棋盘合法性、取消和状态版本检查。不同会话共用同一页面实例，读取的是同一棋盘；过期操作返回版本冲突，模型需要重新观察，不能盲目重试。普通宿主访问范围保持由宿主管理。

## 画面与音效

SVG 棋盘、镜面旋转、光路辉光、位置提示与通关反馈；适配深浅色、窄窗口和减少动态效果偏好。按钮支持键盘操作，镜子有坐标与朝向标签。

音效由 Web Audio 的正弦波与短包络合成，包括旋转、撞墙和通关提示音。首次用户操作后开启音频，可随时静音。组件不下载图片、字体、音频采样或本地模型；AI 调用通过宿主已有会话进行。

## 开发与验证

需要 Node 24，以及相邻的 `pudding-core`、已准备依赖的 `pudding-desktop`。

```sh
PUDDING_CORE_DIR=../pudding-core node scripts/package-widget.mjs light-workshop --dev
node --experimental-strip-types --test test/light-workshop.test.mjs test/widget-languages.test.mjs
node test/light-workshop-ui.cjs
```

打包器执行 Core 源码包校验及 Desktop 的 TypeScript／JS／CSS 编译。开发包位于本目录的 `dev/`；正式包与目录记录由同一个打包器生成，发布包不可覆盖。

规则与接口测试涵盖反射方向、六关可解性、边界与障碍、撤销、编辑、多会话直接访问、位置高亮、取消、并发写入、结束后的读取及保存失败。

UI 测试使用真实 Desktop 编译器、SDK 和隔离的 Electron 窗口，宿主通信与模型响应使用测试夹具；验证界面无 AI 控件、普通会话直接调用、跨会话读取、通关、过期版本、可信手势开启音效、静音、编辑保存及宽窄屏深浅色，并输出截图。需要可启动 Electron 的图形环境，可用 `PUDDING_LIGHT_QA_DIR` 指定输出目录。

真实模型的提示质量和出题趣味性需要单独试玩；程序可解性验证不能替代玩法评估。
