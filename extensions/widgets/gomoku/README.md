# Gomoku

15 × 15 Gomoku. Newly joined online MCP agents fill vacant candidate slots automatically. Internal conversations and **You** are added manually when needed. With two chosen candidates, Start connects the pair; extra candidates stay unselected and can be removed or selected instead. Cancelling a selection is preserved across candidate refreshes. The program randomly assigns Black and White on the first round and whenever either player changes. Another round with the same pair swaps their previous colors, regardless of participant ordering. Each player receives a private invitation naming their assigned color and confirms readiness. Both ready starts a persisted three-second countdown; cancelling readiness cancels it without changing colors. Black moves first. Models use authenticated interfaces; human controls affect only the human's own seat and turn. The next player receives a directed action request; the result is broadcast. Reloading or restarting restores a paused board; continuing resumes it, while explicitly closing the tab resets it.

On a Desktop with the local widget MCP bridge, the same picker also lists connected external clients such as Codex. Explicitly joined agents appear in the candidate pool; two online agents can start directly, or the user can supplement with a conversation or **You**. Manual removal remains available. Reopening the picker refreshes candidates, including connections made after the board opened. The widget uses the host-assigned participant identity and the same readiness, board and move interfaces for every non-human player. Internal conversations keep notification-driven turns; MCP agents wait for those business events through widget_wait. Seat counts and role allocation belong to the game; the shared MCP bridge does not assume two seats. Older hosts keep the existing human/conversation workflow; updating this widget alone does not install the desktop MCP bridge. Get published updates from Studio's widget library. Finish the current game before reloading an updated source revision, whose page state is separate.

Version 1.0.2 listens for candidate changes on hosts that support them. A self-reported model appears as `Model name (MCP)` with host-provided brand artwork; the connection name remains below it. Offline connections stay visible and cannot be invited. The user can remove an external connection from the picker, or the agent can explicitly leave through the host's `widget_disconnect` tool. Neither action resets the retained board. Model declarations and connection management require the updated desktop bridge; older SDK 1 hosts continue using the existing player picker without those controls. Both current and Desktop v0.8.1 compilers accept the source.

Two independent player cards show the real model name, model-brand artwork, conversation and side. Cards stay 192px high through invitation, readiness, countdown, play, results and replay, retaining room for readiness controls and the human comment composer without shifting the board. At widget widths of 680px or more they sit to the right of the board, top-aligned with the square wooden board rather than the comment strip above it; narrower views put them above it. The light background is pure white; the dark background matches Pudding conversations. Controls use neutral gray. Unassigned sides show a dashed circle and “Undecided”. The active player shows an elapsed turn clock backed by the saved turn-start timestamp. When a card has no readiness or composition controls, its lower area shows that player’s total thinking time in large bold digits. Completed-turn totals are saved with each legal move; the active turn is added while running and freezes during pauses and at game end. Replay retains the final match totals. The winning card has a large, slightly tilted gold trophy + WIN stamp at its upper-right corner. It supports light/dark themes and reduced motion; replay hides the badge until returning to the result, and a draw has no badge. Older scores without timing data show a dash rather than an invented total. Only the latest visible player comment appears in a fixed-height strip above the board, with larger model artwork, a black/white side marker and the move number. New comments fade and slide in; long comments scroll slowly, hover or keyboard focus pauses scrolling, and reduced-motion mode disables animation and allows manual scrolling. The strip keeps its space when comments are off or empty. The wooden board remains square, and the player cards do not repeat comments. `placeStone` accepts an optional comment of up to 40 characters for public banter, psychology or playful taunts, while instructing models not to reveal tactical intent or spoil critical board moves; committed with the legal move; a later non-empty comment replaces the strip, while silent moves retain the last message. Humans can compose a comment in their card before clicking an intersection.

The move-number toggle is off by default and labels occupied intersections in chronological order. With numbers visible, a ring marks the latest stone without covering its number. After a finished game with at least one move, Replay opens at the empty board: previous/next buttons and a slider review the score, including the latest comment at the replay cursor in the strip above the board. Back to result restores the final board. Replay and number visibility are local viewing controls; they never write game state, change its version, or send notifications. Starting another round exits replay. Card and board geometry stays fixed throughout viewing.

`placeStone` takes real board coordinates, e.g. `{ "column": "H", "row": 8, "comment": "Center opening" }`. Columns are uppercase **A–O**; rows are numbers **1–15**, with **1 at the bottom and 15 at the top**. Numeric columns are rejected. Board reads and notifications use the same coordinates: `board.text` is one multiline string with the letter header and rows 15 down to 1; the opt-in `history` is the chronological list of `{column,row,stone:"B"|"W",comment?}`; `moveCount` counts individual placements. The history is canonical; numeric rendering cells, current turn, winner, last move and latest player comments are derived. Readiness responses include the caller's identity, readiness and `yourTurn`.

Pause cancels only this game's model work, blocks human and model moves and freezes thinking time. Continue retains the game, resumes pending work, and sends a fresh action request only if an earlier model attempt ended without completing its business action. New game is available while paused: keep the two players, retire old requests, swap colors, reset readiness/history, then prepare and count down again. Change players is available while paused or after the result and opens the picker with the existing pair selected; changing either player draws colors afresh. Pause/continue retains assigned colors. A resumed countdown restarts at three seconds. Each source revision has its own page state; old-format games stay with their old revision, and the new revision starts a fresh game.

The game follows Pudding's Simplified Chinese, Traditional Chinese or English setting live without changing the game state. Visible game errors also follow language changes; interface errors use the language at invocation. Result messages reuse the localized summary, while structured game values stay unchanged. Installed names and existing player comments remain as authored, including literal dollar signs and braces in names. Notification receipts retain their original text across language changes.

Interfaces are called through `widget_invoke({targetID, expectedStateVersion, name, input})`, not standalone tools. Invitations explain the wrapper, the assigned color, readiness (`ready`), and conceding (`resign`, input `{}`). A seated player may resign during either player's turn; both receive the result. There is no timeout forfeiture.

Notifications contain the current board, last move, move count, turn, winner, round and phase, without history. `placeStone` and `resign` return only the last move, move count, turn, winner, round, phase and resignation details; the host adds `stateVersion`. `readBoard` defaults to the current board and participant/seat state; explicitly pass `{includeHistory:true}` to retrieve the full chronological history with comments. Successful readiness operations return seat/readiness/countdown status without board or history. `stateVersion` versions all page state for concurrency checks; `moveCount` alone counts stones. A model can play directly from its notification, without observing or reading again each turn. Stale versions are still rejected before an action runs.

Player identity precedes side and status in document reading order, while the visual card layout remains unchanged. Opening hints distinguish the assigned color, waiting for that player's readiness, waiting for the opponent, and both players ready.
