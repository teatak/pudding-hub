# Email plugin and Email Board

Requires protocol 59 / Plugin API 1.3 for the expanded presets and the matching Desktop. Install the Email plugin and Email Board, create an iCloud, Gmail or custom IMAP/SMTP connection, then select it in the board toolbar.

- iCloud: imap.mail.me.com:993 (TLS), smtp.mail.me.com:587 (STARTTLS), full email address and an Apple app-specific password. [Apple setup](https://support.apple.com/102525).
- Gmail: imap.gmail.com:993 (TLS), smtp.gmail.com:465 (TLS), full email address and a Google app password. Two-step verification is required; some managed/protected accounts cannot use app passwords. [Google setup](https://support.google.com/mail/answer/185833).
- QQ: imap.qq.com:993 / smtp.qq.com:465, TLS, full address and a client authorization code.
- NetEase 163/126: imap.163.com / imap.126.com:993 and smtp.163.com / smtp.126.com:465, TLS, full address and a client authorization code.
- Yahoo: imap.mail.yahoo.com:993 / smtp.mail.yahoo.com:465, TLS and an app password.
- Fastmail: imap.fastmail.com:993 / smtp.fastmail.com:465, TLS and an app password with Mail permission. Basic plans do not support third-party clients.
- Custom: supply both hosts, ports and TLS/STARTTLS modes. Certificates must be trusted by the system. Optional login overrides default to the email address; an unset SMTP password defaults to the main password. SMTP supports PLAIN and LOGIN. OAuth-only providers, plaintext transport and certificate bypasses are unsupported.

Preset forms ask only for the email address and app password or client authorization code. Connection names are generated automatically and can be edited later. Server and login settings are automatic. The custom IMAP/SMTP form exposes the full server and optional login settings.

Credentials use the encrypted host store and are write-only in settings. Blank secret edits preserve existing values; clearing an optional SMTP password is explicit. Saving authenticates both protocols without sending. Password rotation preserves mailbox identity, bindings and drafts. A different IMAP server/login requires a new connection and explicit selection. Configuration revisions reject stale reads and concurrent saves.

The board reads INBOX on demand, one card per message. Search is plain text, not Gmail syntax; each page searches up to 5,000 UID positions and an empty page can still have older results. Lists fetch metadata only. Plain text and HTML are each bounded to 64 KiB. HTML messages default to sanitized rich text with a plain-text toggle; HTML-only messages also have a text fallback. Formatting, styles, responsive layouts, tables and HTTP(S)/mailto links are preserved in an isolated document. HTTPS images, including avatars in the body, load by default. Scripts, forms and embedded frames remain disabled. Attachments expose metadata only. MIME-encoded sender and recipient display names are decoded. Opening a successfully loaded message in the UI adds the server's Seen flag; the red unread dot disappears only after success. A failed update retains the dot and offers retry without blocking the body. Lists, refreshes and model reads stay read-only. This version requires host protocol 61 or later.

The board currently focuses on inbox searching and reading. Status categories and note/reply-draft editing are temporarily unavailable in both the UI and board interfaces. Existing local categories, notes and drafts are retained without rewriting them; all inbox messages remain visible regardless of old local status. Full bodies and attachments are not stored locally. Apart from adding Seen when opened, the board does not change remote flags, labels or drafts. The plugin's model tool can send plain-text new messages and replies when the user requests sending. Never automatically retry `email_send_uncertain`. SMTP acceptance is not guaranteed delivery. Sent copies depend on the server; the adapter does not append duplicates, and some custom/iCloud servers may not save a copy automatically.

The withdrawn Gmail Board's historical packages and local data remain intact. The replacement is named Email Board and uses a separate `emailBoard` namespace keyed by mailboxID. Gmail API IDs and IMAP UIDs are incompatible, so old cards are not automatically migrated. Existing OAuth connections cannot be converted to app passwords automatically.

Setup references: [QQ](https://help.mail.qq.com/detail/106/985), [NetEase](https://help.mail.126.com/), [Yahoo](https://help.yahoo.com/kb/SLN4075.html), [Fastmail](https://www.fastmail.help/hc/en-us/articles/1500000278342-Server-names-and-ports). Outlook.com requires OAuth2 and is not offered as a password preset.
