# Gomoku

15 × 15 Gomoku. Starting from two current conversations invites them directly. With fewer than two, the picker fills the missing player from conversations or **You**. Each invited player chooses one available side and gets ready. Both ready starts a persisted three-second countdown; cancelling readiness or leaving a seat cancels it. Black moves first. Models use authenticated interfaces; human controls affect only the human's own seat and turn. The next player receives a directed action request; the result is broadcast. Reloading or restarting restores a paused board; continuing resumes it, while explicitly closing the tab resets it.

Two independent player cards show the real model name, model-brand artwork, conversation and side. They stay 192px high through invitation, readiness, countdown, moves and results. At widget widths of 680px or more they sit to the right of the board; narrower views put them above it. The light background is pure white; the dark background matches Pudding conversations. Controls use neutral gray. Unassigned sides show a dashed circle and “Undecided”. The active player shows an elapsed turn clock backed by the saved turn-start timestamp. Comments appear only inside the cards, in a compact two-line box with the move number inline before the sentence. `placeStone` accepts an optional comment of up to 40 characters, committed with the legal move; the player's next move replaces it. Humans can compose a comment in their card before clicking an intersection.

`placeStone` takes real board coordinates, e.g. `{ "column": "H", "row": 8, "comment": "Center opening" }`. Columns are uppercase **A–O**; rows are numbers **1–15**, with **1 at the bottom and 15 at the top**. Numeric columns are rejected. Read/action results and notifications use the same coordinates: `board.text` is one multiline string with the letter header and rows 15 down to 1; `history` is the chronological list of `{column,row,stone:"B"|"W",comment?}`; `moveCount` counts individual placements. The history is canonical; numeric rendering cells, current turn, winner, last move and latest card comments are derived. Seat operations include the caller's identity, readiness and `yourTurn`.

Pause cancels only this game's model work, blocks human and model moves and freezes thinking time. Continue retains the game, resumes pending work, and sends a fresh action request only if an earlier model attempt ended without completing its business action. New game is available while paused: keep the two players, retire old requests, reset sides/readiness/history, then select sides and count down again. A resumed countdown restarts at three seconds. Each source revision has its own page state; old-format games stay with their old revision, and the new revision starts a fresh game.

The game follows Pudding's Simplified Chinese, Traditional Chinese or English setting live without changing the game state. Installed names and existing player comments remain as authored. Notification receipts retain their original text across language changes.

Move notifications omit past comments from history to stay within the host’s 32 KiB limit, while `readBoard` keeps the complete score and comments. They include the public board and the host's page-state version. A model that already knows `placeStone` can move directly from that snapshot without calling `widget_observe` each turn. Read interfaces or page observation remain available when more context is needed; stale versions are still rejected before a move runs.

Requires source-package format 2, protocol 24 (host locale and candidate model metadata) and SDK 1. See [development guide](../../docs/widget-development.md). Historical releases remain immutable; the current package has its own page-state revision.
