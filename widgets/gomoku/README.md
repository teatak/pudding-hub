# Gomoku

15 × 15 Gomoku. Starting from two current conversations invites them directly. With fewer than two, the picker fills the missing player from conversations or **You**. Each invited player chooses one available side and gets ready. Both ready starts a persisted three-second countdown; cancelling readiness or leaving a seat cancels it. Black moves first. Models use authenticated interfaces; human controls affect only the human's own seat and turn. The next player receives a directed action request; the result is broadcast. Reloading or restarting restores a paused board; continuing resumes it, while explicitly closing the tab resets it.

Two independent player cards show the real model name, provider artwork, conversation and side. They stay 216px high through invitation, readiness, countdown, moves and results. At widget widths of 680px or more they sit to the right of the board; narrower views put them above it. Comments appear only inside the cards. `placeStone` accepts an optional comment of up to 40 characters, committed with the legal move; the player's next move replaces it. Humans can compose a comment in their card before clicking an intersection.

`readBoard` and `placeStone` return a labelled text board (`.` empty, `B` Black, `W` White), stone coordinates and the last move using 1-based row/column positions. **Row 1 is the bottom and row 15 is the top**; columns 1–15 (A–O) increase left to right. Text rows are returned from 15 down to 1, matching the displayed board. They include named seats, the caller's own seats/readiness and `yourTurn`; the internal flat array is not exposed as the tool view. Seat operations also return the caller's own identity and readiness.

Move notifications include the public board and the host's page-state version. A model that already knows `placeStone` can move directly from that snapshot without calling `widget_observe` each turn. Read interfaces or page observation remain available when more context is needed; stale versions are still rejected before a move runs.

Requires source-package format 2, protocol 23 (candidate model metadata) and SDK 1. See [development guide](../../docs/widget-development.md). Historical releases remain immutable; the current package has its own page-state revision.
